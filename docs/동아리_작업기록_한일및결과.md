AI TAB 악보 자동 생성 앱 작업 기록(한 일 및 결과)입니다. 작성일은 2026년 7월 23일이고, 아이디어 스케치 단계부터 Phase 0 기술 PoC까지의 기간을 다룹니다.

---

## 1. 프로젝트 한 줄 요약
사용자가 곡을 업로드하면 AI가 베이스/기타/드럼 TAB 악보를 자동 생성해주는 앱. MVP는 **베이스 라인 TAB 자동 생성**부터 검증.

## 2. 아이디어 선정 과정
- 초기 후보 2개(① AI TAB 악보 앱, ② 듀오링고식 경제학습 앱)를 고객층·Pain Point·수익모델 기준으로 비교 정리
- 경쟁사 분석(Ultimate Guitar, Moises)을 통해 "AI 자동 생성 + 정밀 프렛 단위 TAB"이라는 시장 공백 확인
  - Ultimate Guitar: 사람이 직접 채보하는 크라우드소싱이라 최신곡·마이너 곡은 커버 불가, 자동화 없음
  - Moises: AI 자동화는 있으나 코드 차트 수준이지 프렛 단위 TAB은 아님
- **① AI TAB 악보 앱으로 방향 확정** — 기술 난이도는 높지만 성공 시 진짜 기술 해자(moat) 확보 가능하다고 판단

## 3. Phase 0 기술 PoC — 한 일

실제 곡("일당백 - 데카당", "오디티스")으로 로컬 환경(Python, CPU 전용)에서 전체 파이프라인을 처음부터 끝까지 구축·검증함.

| 단계 | 한 일 | 사용 기술 |
|---|---|---|
| 음원 분리 | 믹스 음원에서 베이스 트랙만 분리 | Demucs |
| 음정 검출 | 분리된 베이스 트랙에서 음정(피치) 추출 | torchcrepe (계획했던 Basic Pitch는 Python 3.13 비호환으로 대체) |
| 노이즈 필터링 | 조성(key) 자동 추정 후, 스케일 밖 음 중 극히 짧은 노트를 오검출로 필터링 | Krumhansl-Schmuckler 키 추정 알고리즘 |
| 운지 최적화 | 같은 음도 여러 (줄,프렛) 조합이 가능한데, 실제 연주자가 편하게 이어칠 수 있는 조합을 자동 선택 | 비용함수 기반 DP + "포지션 박스" 방식 + 국소 앵커 2차 최적화 |
| 리듬 정렬 | 템포(BPM)·비트 타임스탬프 추정 후 각 노트를 마디/박자 단위로 양자화 | librosa 비트 트래킹 |
| 악보 렌더링 | 결과를 정식 TAB 악보(빔·쉼표·마디선 포함, 4마디씩 한 줄)로 시각화 | MusicXML 변환 + AlphaTab |

## 4. 결과 / 성과
- **엔드투엔드 파이프라인 동작 확인**: 음원 분리 → 피치 추출 → 노이즈 필터링 → 운지 최적화 → 리듬 정렬 → TAB 렌더링까지 로컬 CPU에서 완주
- **운지 자연스러움 대폭 개선**: 초기엔 "치기 힘들다"는 피드백 → 실제 베이스 연주 방식(손 위치 고정 후 4개 손가락으로 여러 줄을 넘나드는 "포지션 박스" 개념)을 비용함수에 반영해 훨씬 자연스러운 결과로 개선
- **조성 추정 정확도 검증**: 일당백-데카당 곡에서 G minor로 자동 추정(상관계수 0.848) → 원곡 PDF의 실제 코드 진행(Gm7 기반)과 정확히 일치
- **원곡 대비 구조적 유사성 확인**: 코드 진행에 따른 저음역대 이동, 4마디 반복 패턴(Gm7-C7-Cm7-D7), 솔로 구간 하이라이트(15~17프렛) 등이 실제 원곡 TAB과 구조적으로 유사하게 재현됨
- **전문 악보 렌더링 수준 확보**: Songsterr 스타일(오선 없이 TAB 숫자 + 리듬 빔/꼬리만 표시)의 시각화 구현, 실제 음악 이론 기반 마디/빔 그룹핑까지 반영

## 5. 발견한 한계 / 리스크
- **템포(BPM) 자동 감지의 신뢰도 문제**: 오디티스 곡 테스트에서 실제 BPM(78)과 자동 감지값이 불일치(옥타브 오류 패턴) → 자동 감지만으론 부족, 사용자 수동 입력/보정 기능이 실서비스에 필요하다는 결론
- **음표 길이(리듬) 과다 분류 가능성**: 32분음표로 분류되는 노트가 많아 실제 속도 반영인지 검출 오차인지 추가 검증 필요
- **조성 추정은 곡 전체 단일 조성 가정**: 코드 전환 구간에서는 오탐 가능성 있음, 구간별 코드 인식 결합이 향후 과제
- **저작권 리스크**: 원곡 음원 업로드 기반 서비스라 개인 학습용 명시/음원 삭제 정책이 필요 (계획서 8번 섹션에 정책 초안 있음)
