# 작업 브리핑 (2026-08-12)

**한 줄 요약**: Stand By Me 곡 악보를 다시 뽑아보다가 파이프라인 자체의 정확도 버그 3개를 발견해서 고쳤습니다. 이 곡 하나만이 아니라 앞으로 처리할 모든 곡에 적용되는 개선입니다.

- 커밋: [`b3b2dbd`](https://github.com/chldbfk/bass-copy/commit/b3b2dbd) — `main` 브랜치에 푸시 완료
- 결과물: `songs/Stand-By-Me/outputs/` (ASCII TAB, MusicXML, AlphaTab HTML)

## 1. 무슨 문제가 있었나

Stand By Me(20초짜리 인트로 클립)로 베이스 TAB을 뽑았는데, 실제 곡을 들으면서 확인해보니 여러 군데가 원곡과 안 맞았습니다. 하나씩 원인을 추적했습니다.

| 증상 | 원인 | 심각도 |
|---|---|---|
| 리듬이 16분음표로 잘게 쪼개져 지저분함 | 곡마다 "단순 리프인지" 사람이 판단해서 리듬 어휘(4분/8분 vs 16분까지)를 골라줘야 했음 — 자동화가 안 돼 있었음 | 중 |
| 베이스 소리가 나는데도 노트가 안 잡히는 구간이 많음 | 피치 검출 신뢰도(periodicity) 임계값 방식이 베이스의 디케이(decay) 특성과 안 맞아서 **전체 구간의 45%가 통째로 버려지고 있었음** | 높음 |
| ASCII TAB에서 마디 합계가 4박이 안 맞아 보임 | 쉼표를 아예 표시 안 하고 있었음(MusicXML은 원래 정상) | 중 |
| 쉼표 넣었는데도 마디 합계가 4.5박처럼 보임 | 표시 라벨이 독립적으로 반올림되면서 서로 안 맞았음(내부 타이밍 자체는 정확했음) | 낮음(표기만) |
| 텍스트로 말한 "마디 6"과 실제 렌더된 악보의 "마디 6"이 다른 내용 | **마디 번호 자체가 하나씩 밀려 있었음** — 자동감지된 첫 박자 앵커가 실제 첫 음보다 늦어서 첫 음이 "마디 0"이라는 비정상 번호에 들어가고 이후 다 밀림 | 높음 |
| 특정 구간에 없는 음(G#2)이 하나 껴 있음 | 개별 노이즈 노트(피치 검출 오탐) | 낮음(개별 케이스) |

## 2. 코드에 뭘 고쳤나

**`poc_pitch_extract.py`** — 노트 경계 산출 방식을 완전히 바꿈
- 기존: "피치가 바뀌는 시점 + 신뢰도가 임계값(0.5) 아래로 내려가는 시점"으로 노트를 끊음 → 베이스는 어택 후 소리가 잦아드는 악기라 이 방식이 구조적으로 안 맞았음
- 변경: `librosa.onset.onset_detect`로 실제 타건(어택) 시점을 먼저 잡고, 그 구간 안에서 신뢰도 높은 프레임들의 중앙값 피치를 노트 음높이로 사용
- 효과: 오디오 커버리지 **44% → 94%**

**`poc_rhythm_quantize.py`**
- `infer_note_grid()` 신설: 노트 시작 간격(IOI)이 8분음표 격자에 얼마나 잘 맞는지 통계로 계산해서 리듬 어휘(SIMPLE vs 기본)를 자동 선택. `quantize_notes`/`build_musicxml`의 기본 동작이 됨 — **더 이상 곡마다 사람이 판단 안 함**
- `quantize_notes`에 마디 앵커 보정 추가: 자동감지 앵커가 실제 첫 노트보다 늦으면 마디 단위로 통째로 앞당겨서 마디 1부터 정상 시작하도록 함

**`poc_final_tab.py`**
- ASCII TAB에 쉼표를 명시적으로 표기하도록 수정 (`insert_rests()` 재사용)
- `_close_measure_labels()` 신설: 반올림 오차를 마지막 항목에 몰아서 마디 라벨 합계가 항상 정확히 4박이 되도록 보정

**`poc_export_musicxml.py`** — `build_musicxml`도 `infer_note_grid` 기본 사용하도록 연결

## 3. Stand By Me 최종 상태

- 48노트, A major, BPM 120(수동 확정), 11마디(1~11번, 정상 번호)
- 크로매틱 슬라이드 1건 자동 검출 (F2→E2→D#2, 6번 마디)
- 노이즈 노트(G#2, 12.84s) 제거 완료
- 리듬은 4분/8분음표 위주(16분음표 없음), 쉼표 정확히 표기됨

## 4. 아직 확인 안 끝난 부분

- **6번 마디의 D2/D#2 반복 노트**(9.87~10.86s 구간)가 실제로 각각 2번씩 맞는지 아직 확인 중 — 다음에 이어서 검증 필요
- 이런 "실측 대비 노트 개수/타이밍 검증"은 곡 하나를 완벽하게 만드는 게 목적이 아니라, **여러 곡을 처리하며 파이프라인 정확도를 계속 쌓아가는 과정**입니다 (계획서.md 11번 섹션 프레임). 다음 곡 작업 때도 이번에 고친 것들(특히 마디 번호/커버리지)이 잘 작동하는지 같이 확인해주세요.
